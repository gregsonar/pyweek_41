# Into the Dark — Developer Reference

Warning: work in progres! 

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate.bat
pip install -r requirements.txt
python run.py           # обычный запуск
python run.py --debug   # подробный лог в stdout
```

## Тестирование
Тесты лежат в папке 'tests\'. Для запуска нужно установить pytest:
```bash
pip install pytest
python -m pytest tests/ -v # Запуск всех тестов
```

## Корень

| Файл | Назначение |
|------|-----------|
| `run.py` | Точка входа. Инициализирует `Game`, регистрирует все сцены, запускает игровой цикл. Принимает флаг `--debug` для включения подробного логирования. |
| `settings.py` | Все игровые константы. Организованы в `frozen dataclass`-ы по доменам: `DISPLAY`, `PHASE`, `LIGHT`, `PLAYER`, `MONSTER`, `WORLD`, `RESOURCES`, `RECIPES`. Магических чисел в остальном коде быть не должно — только ссылки сюда. |
| `requirements.txt` | Единственная зависимость: `pygame-ce`. |

---

## `core/` — каркас движка

Код, не зависящий от конкретной игровой логики. Менять здесь нужно редко.

| Файл | Назначение |
|------|-----------|
| `game.py` | Главный класс `Game`. Владеет `pygame`-окном, часами, и тремя синглтонами: `assets`, `bus`, `scenes`. Содержит основной цикл с кэпом `dt` (защита от spiral-of-death при потере фокуса). Ничто снаружи не должно вызывать `pygame.init()`. |
| `scene_manager.py` | Регистрирует сцены по имени, маршрутизирует события и вызовы `update`/`draw` к активной сцене. Переключение сцен **отложено** до начала следующего кадра — это предотвращает мутацию стека во время итерации. |
| `event_bus.py` | Синхронная шина событий (pub/sub). Класс `Events` содержит все имена событий как строковые константы — не используйте сырые строки в подписках. Исключения в слушателях логируются и не роняют игру. |
| `asset_loader.py` | Централизованная загрузка и кэширование ресурсов. При отсутствии файла возвращает пурпурный placeholder — игра не падает. Пути передаются относительно `assets/`. |

---

## `scenes/` — экраны игры

Каждая сцена реализует `BaseScene` и изолирована от остальных.

| Файл | Назначение |
|------|-----------|
| `base_scene.py` | Абстрактный базовый класс. Объявляет интерфейс: `on_enter`, `on_exit`, `handle_event`, `update`, `draw`. Хранит ссылки на `game` и `manager`. |
| `menu_scene.py` | Главное меню. Переход в игру по Enter/клику, выход по Escape. |
| `game_scene.py` | Главная игровая сцена. Содержит FSM фаз: `DAY → TRANSITION_TO_NIGHT → NIGHT → TRANSITION_TO_DAY → ...`. Оркестрирует все системы и сущности. Управляет подписками на события и отписывается в `on_exit`. |
| `gameover_scene.py` | Экран смерти. Показывает количество пережитых ночей. Хранит `nights_survived` — это поле записывает `game_scene` перед переключением. |

## `systems/` — игровые системы

Системы не хранят состояние сущностей — они обрабатывают данные, которые получают извне.

| Файл | Назначение |
|------|-----------|
| `light_system.py` | **Приоритет #1.** Raycasting-тени на основе алгоритма visibility polygon. Для каждого источника света: собирает отрезки препятствий → кастует лучи под углами ко всем вершинам → строит освещённый полигон → вырезает его из тёмного оверлея через `BLEND_RGBA_SUB`. Также рисует мягкий glow-ореол без шейдеров. |
| `ai_system.py` | **Приоритет #2.** Владеет всеми активными монстрами. Каждый монстр живёт в одном из четырёх состояний FSM: `WANDER → ALERT → HUNT → FLEE`. Переходы зависят от близости игрока и нахождения в свете. Управляет волнами спавна с нарастающей сложностью. |
| `collision.py` | AABB-коллизии с пространственной сеткой для O(1)-поиска соседей. Метод `move()` возвращает скорректированную позицию с axis-separated разрешением столкновений. Перестраивается при смене карты через `load_world()`. |
| `craft_system.py` | Крафт и строительство. Рецепты живут в `settings.RECIPES` — система не знает о конкретных предметах. `craft()` списывает ресурсы из инвентаря и публикует `Events.ITEM_CRAFTED`. |

## `entities/` — игровые объекты

Сущности хранят своё состояние и умеют себя рисовать. Логика обновления частично делегирована системам.

| Файл | Назначение |
|------|-----------|
| `player.py` | Игрок. Обрабатывает ввод (WASD + F + E + Shift), движение с коллизиями, расход топлива фонаря, получение урона, инвентарь. Публикует события через `bus` — не знает о сценах напрямую. |
| `monster.py` | Монстр. Хранит позицию, HP, скорость, тип и текущее состояние FSM (которое пишет `AISystem`). Три типа: `BASIC`, `STALKER`, `SMASHER` — характеристики в таблице `_TYPE_STATS`. |
| `light_source.py` | Стационарный источник света: костёр, факел, фонарь, свеча. Хранит `fuel`, `radius`, `intensity`. `LightSystem` опрашивает `world.light_sources` каждый кадр. |

---

## `world/` — карта и генерация

| Файл | Назначение |
|------|-----------|
| `world.py` | Контейнер текущей карты. Хранит `tiles`, `obstacles`, `containers`, `light_sources`. Предоставляет `obstacle_rects()` для `CollisionSystem` и `obstacle_segments()` для `LightSystem`. |
| `generator.py` | Процедурная генерация. `generate_day_map(night)` — рассыпает препятствия и контейнеры с лутом по таблице `_LOOT_TABLE`. `generate_night_map(night, inventory)` — строит лагерь: костёр в центре, кольцо скал вокруг. Сложность растёт с каждой ночью. |

---

## `ui/` — интерфейс

| Файл | Назначение |
|------|-----------|
| `hud.py` | HUD: фаза и таймер (центр), HP и полоска фонаря (лево), инвентарь (низ-лево), подсказки (низ-право). Намеренно **stateless** — получает все данные аргументами в `draw()`, не хранит ссылок на игровые объекты. |

## `assets/`

| Каталог | Что класть |
|---------|-----------|
| `sprites/` | PNG-спрайты и спрайтшиты. Путь передаётся в `assets.image("sprites/player.png")`. |
| `sounds/` | Звуки в любом формате, поддерживаемом SDL (`wav`, `ogg`, `mp3`). Путь в `assets.sound("sounds/campfire.ogg")`. |
| `fonts/` | TTF/OTF шрифты. Путь в `assets.font("myfont.ttf", 24)`. |

Если файл не найден, `AssetLoader` логирует предупреждение и возвращает placeholder — игра не падает.

## `tests/`

Запуск: `pytest tests/ -v` (pygame инициализируется headless автоматически, дисплей не нужен).

| Файл | Что проверяет | Зачем это важно |
|------|--------------|-----------------|
| `conftest.py` | Общие фикстуры: `bus`, `player`, `basic_world`, `ai`, `collision`, `craft`. Инициализирует pygame без дисплея через `SDL_VIDEODRIVER=dummy`. | Без этого каждый тестовый файл должен был бы поднимать pygame вручную. Все тесты получают готовые объекты одной строкой — `def test_...(self, player, bus)`. |
| `test_settings.py` | Проверяет, что константы из `settings.py` не противоречат друг другу: радиус фонаря больше костра, скорость перезарядки меньше скорости расхода, рецепты используют только известные ресурсы и т.д. | Дизайнер может случайно поставить неверное значение и сломать баланс. Тесты ловят такие ошибки немедленно, даже если игра внешне запускается нормально. |
| `test_event_bus.py` | Проверяет, что подписчики получают события, отписка работает, одна и та же функция не вызывается дважды, и что если один подписчик упал с ошибкой — остальные всё равно получат событие. | Шина событий используется везде. Тихая ошибка в ней (например, блокировка остальных после краша) приведёт к непредсказуемому поведению всей игры. |
| `test_scene_manager.py` | Проверяет порядок вызовов `on_exit` / `on_enter`, что переключение сцены не применяется в середине кадра (а только в начале следующего), и что события маршрутизируются в активную сцену. | Переключение сцены «вживую» во время `update()` — классический источник крашей. Этот тест фиксирует намеренное архитектурное решение и не даст его случайно сломать. |
| `test_light_system.py` | Проверяет математику raycasting (пересечение луча и отрезка, сортировку полигона), что препятствия создают тень, нет дублирующих вершин, и главное — что два перекрывающихся источника света не делают центр темнее, чем один источник. | Последний тест — прямая проверка исправленного бага с double-subtract: раньше два источника в одной точке взаимно гасили свет вместо того, чтобы суммировать его. |
| `test_collision.py` | Проверяет, что стена останавливает движение, что можно скользить вдоль стены (не застревать), что пространственная сетка корректно сбрасывается при загрузке новой карты. | Коллизии затрагивают и игрока, и монстров. Ошибка здесь означает либо прохождение сквозь стены, либо полное застревание. |
| `test_craft_system.py` | Проверяет все сценарии крафта: хватает/не хватает ресурсов, ресурсы списываются корректно, публикуется событие, рецепты используют данные из `settings.py` а не захардкоженные значения. | Тест `test_returns_all_when_wealthy` одновременно проверяет, что все рецепты из конфига реально доступны и не содержат опечаток в именах ингредиентов. |
| `test_entities.py` | Тестирует три сущности вместе: `Player` (блокировка ввода, расход и перезарядка фонаря, зажим у границы экрана, инвентарь, смерть), `Monster` (типы, масштабирование сложности, `targets_campfire`), `LightSource` (топливо, HP костра, интенсивность). | Каждое из этих свойств было добавлено в виде фикса. Тесты не дадут регрессии: если `input_locked` вдруг перестанет работать или костёр перестанет получать урон, тест упадёт. |
| `test_ai_system.py` | Проверяет все переходы FSM (WANDER→ALERT→HUNT→FLEE и обратно), что монстры убегают к краю карты и деспаунятся, что урон от фонаря пропорционален `dt`, что спавн происходит за экраном и усложняется с каждой ночью. | FSM-тесты вызывают `_update_fsm` напрямую, минуя полный игровой цикл — это делает их детерминированными и быстрыми. |
| `test_world.py` | Проверяет свойство `world.campfire`, геометрические хелперы (`obstacle_rects`, `obstacle_segments`), поведение контейнеров при взаимодействии (лут выдаётся один раз), обновление топлива костра. | `world.campfire` — единственная точка доступа к костру для AISystem и GameScene. Если оно вернёт `None` когда не должно, SMASHER перестанет атаковать костёр без каких-либо ошибок в логах. |
| `test_generator.py` | Для дневной карты: препятствия и контейнеры выровнены по сетке 32px, центральная зона свободна (проверяется 10 раз на разных seed'ах), контейнеры не перекрываются препятствиями и всегда имеют хотя бы один свободный сосед. Для ночной: костёр в центре, кольцо скал вокруг, нет контейнеров. | Генератор работает с рандомом, поэтому тесты запускаются в цикле на нескольких seed'ах — нельзя проверить одним прогоном. Тест на `_snap` параметризован по конкретным значениям, это живая документация того, как должна работать функция. |

## Поток данных между системами

```
run.py
  └─ Game (main loop)
       ├─ SceneManager → GameScene
       │    ├─ World (карта + препятствия)
       │    ├─ Player (ввод → движение → инвентарь)
       │    ├─ LightSystem (obstacle_segments + light_sources → shadow overlay)
       │    ├─ AISystem (монстры: FSM + спавн-волны)
       │    ├─ CollisionSystem (obstacle_rects → AABB)
       │    ├─ CraftSystem (inventory + recipes → события)
       │    └─ HUD (stateless render)
       └─ EventBus (развязка между Player / AISystem / GameScene)
```

## Соглашения

- Все константы — в `settings.py`, магических чисел в коде нет.
- Для событий используются строковые константы из `Events`, не сырые строки.
- Системы (`systems/`) не импортируют друг друга напрямую — общение через `EventBus`.
- Type hints обязательны в новом коде.
- Ошибки не глотаются молча (`except: pass` запрещён).
